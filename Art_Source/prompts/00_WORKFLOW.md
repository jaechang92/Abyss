# dark_blade 애니메이션 제작 절차 — NovelAI Diffusion V5

> 폼 하나(dark_blade)의 9상태 애니메이션을 끝까지 만드는 순서.
> 프롬프트는 `build.py`가 조립한다. 손으로 이어 붙이지 않는다 — 한 글자만 달라져도 다른 사람이 나온다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `01_character.txt` | **정체성 SoT.** 이 캐릭터가 누구인가. 고치려면 여기서만 |
| `02_rules.txt` | 프레이밍·품질·투명배경·부정 프롬프트. 상태가 바뀌어도 안 바뀐다 |
| `states/*.txt` | 상태별 프레임 포즈 9종 |
| `build.py` | 위 셋을 합쳐 `assembled/`에 낸다. **한글 유출 차단 포함** |
| `assembled/` | 산출물. git 비추적 — 언제든 다시 만들어진다 |

```bash
python Art_Source/prompts/build.py           # 전 상태
python Art_Source/prompts/build.py idle run  # 지정 상태만
```

`assembled/00_ALL.md`에 전부 모여 있어 파일을 하나씩 열지 않아도 된다.

## 프레임 수

총 **45프레임 + 시트 9장**.

| 상태 | 프레임 | 루프 | 비고 |
|---|---:|---|---|
| idle | 4 | ○ | **핑퐁 재생으로 6프레임** — 호흡은 왕복이라 되감아도 된다 |
| run | 8 | ○ | 핑퐁 불가(한 방향 순환), 미러 불가(갑옷 비대칭) |
| jump | 3 | × | 마지막 프레임 유지 |
| fall | 3 | ○ | 루프 이음매가 티 나지 않게 |
| dash | 4 | × | |
| attack_light | 6 | × | 무기 포함 |
| attack_heavy | 8 | × | 무기 포함. 프레임 4에서 **정지**가 무게를 만든다 |
| hit | 3 | × | 짧게. 길면 조작 뺏긴 느낌 |
| dead | 6 | × | 마지막 프레임 유지 |

## 순서

### 1. 설정 고정

- **NovelAI Diffusion V5 Full** — Curated는 인페인팅이 아직 V4.5다
- Seed·해상도·Steps를 **한 애니메이션 안에서 고정**
- 🔴 **한 상태는 한 세션에서 끝낸다.** 날짜를 넘기면 같은 설정이어도 색온도가 갈린다

### 2. 태그 검증 (한 번만)

`01_character.txt`의 태그를 입력창에 넣어 **자동완성 점의 진하기**를 본다.
흐린 태그는 모델이 모르는 태그이고, 모르는 태그는 그냥 무시된다.
안 먹는 게 있으면 **`01_character.txt`에서 고친다** — 조립본을 고치면 다음 빌드에 날아간다.

### 3. 기준 프레임 확정

`assembled/idle_f01.txt`로 여러 장 뽑아 **한 장을 고른다.**
이 한 장이 이후 모든 프레임의 출발점이므로 여기서 타협하지 않는다.

확인할 것:
- 얼굴이 안 보이는가 (후드 안은 그림자뿐)
- 발광색이 주황 하나뿐인가 (두 번째 색이 끼면 폼 구분이 무너진다)
- **알파 경계** — 확대해서 반투명 테두리가 남았는지 본다. 남으면 프레임마다 깜빡인다
- 전신이 다 들어왔는가

### 4. 프레임 생성 — 두 갈래

**(A) 인페인팅** — 기본 경로
1. 기준 프레임을 올린다
2. 바꿀 부위만 마스크한다 (상태 파일 주석에 어디를 칠할지 적혀 있다)
3. 같은 프롬프트에 해당 프레임 포즈만 바꿔 넣는다
4. 반복

**안 건드린 픽셀은 변할 수 없다** — 정체성 드리프트를 원천에서 막는 게 이 방식의 값이다.

**(B) 시트** — `*_sheet.txt`
한 번의 생성으로 전 프레임을 한 장에. 같은 생성이라 색이 갈리지 않는다.
⚠️ 부정 프롬프트가 낱장과 **다르다**(`assembled/*_sheet.txt` 아래쪽에 붙어 있다).

### 5. 먼저 4프레임으로 관통한다

🔴 **9상태를 다 뽑기 전에 idle 하나를 Unity 재생까지 끝낸다.**
후처리·임포트·재생에서 나올 문제를 45프레임 뽑은 뒤에 발견하면 전부 다시 해야 한다.

### 6. 후처리 (필수)

낱장을 그대로 쓰면 재생할 때 떨린다. 도구가 아직 없으므로 **만들어야 한다**:

| 도구 | 하는 일 | 왜 |
|---|---|---|
| 시트 분해 | 멀티패널을 프레임으로 자름 | 연결 성분 추출 |
| **팔레트 통일** | 전 프레임 공통 팔레트(median-cut) 적용 | 프레임별 색온도 출렁임 제거 |
| 알파 임계 고정 | 투명 경계를 같은 값으로 | 윤곽선 깜빡임 제거 |
| **무게중심 정렬** | 알파 가중 중심을 셀 중심에 | 🔴 바운딩박스 중심으로 하면 **무기가 뻗은 프레임에서 몸통이 반대로 밀린다** |
| 아틀라스 조립 | 균일 셀 격자로 묶음 | Unity 슬라이스 전제 |

`Tools/ArtPipeline/prepare_form_sprite.py`의 **발밑 피벗 실측**이 무게중심 정렬의 원형이다 —
정지 스프라이트에서 한 번 어긋나던 문제가 프레임에서는 매 프레임 흔들림이 된다.

### 7. Unity 임포트

1. 시트를 **Multiple** 모드로 임포트 → 균일 격자 슬라이스
2. `AnimationClip` 생성. **노출은 균등하게 주지 않는다** —
   공격은 예비를 길게, 임팩트를 짧게(각 상태 파일에 권장 틱이 있다)
3. `PlayerAnimationIds`의 상태 이름과 **클립 이름을 일치**시킨다
4. 클립이 없는 상태는 **폴백 사슬**이 대신 받는다 — 다 그릴 때까지 화면은 안 멈춘다

### 8. 검증

`Tools/ArtPipeline/measure_consistency.py`로 잰다. **방향이 둘로 갈린다:**

- **프레임 간** 팔레트 → **겹침이 높아야** 좋다 (같은 사람이어야 하므로)
- **폼 간** 팔레트 → **겹침이 낮아야** 좋다 (구분돼야 하므로)

기준값은 웹 image_gen 시절 것(폼 내부 81.7~90.4%)이라 **V5 기준으로 다시 실측**한다.
