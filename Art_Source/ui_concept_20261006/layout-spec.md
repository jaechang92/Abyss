# Abyss UI — 파편과 기록판

2026-10-06. 화면 설계 제안 v1. 생성 이미지는 미술 후보이며 이 문서 좌표와 게임 데이터가 구현 기준이다.

## 근거와 방향

- 들은 것: `Docs/game-design/00-concept.md`의 형태 교체 × 무기 × 드래프트. 형태 두 개와 액티브 스킬 두 개는 실제 Presenter와 대조했다.
- 들은 것: `Art_Source/stage1_slice_20260930/README.md`의 사용자 채택 v1. 청회색 석조, 생활 도구, 밝은 원경과 공간감.
- 들은 것: `Art_Source/10_BIBLE/04-palette.md`. 색은 시너지 축, 형태는 실루엣/표식으로 구별. 월드 색과 UI 정보색의 역할을 나눈다.
- 지어낸 것: 비대칭으로 겹친 두 석판과 작은 각인 눈금을 UI 공통 모티프로 사용한다. 형태 교체와 축적된 기록을 표현하기 위한 디자인 제안이다. 소설의 고유 문양으로 주장하지 않는다.
- 지어낸 것: 짙은 청회색 평면, 얇은 산화 금속 테두리, 모서리의 파편 장식. 화면 중앙은 장식을 줄이고 텍스트/아이콘의 여백을 보장한다.

옛 ADR-008 본문과 최근 Art_Source 사이에 화풍 변경 이력이 있다. 이번 제안은 최신 Art_Source와 사용자가 고른 Stage1 v1의 픽셀 면을 기준으로 삼는다.

## 공통 좌표·가독성

기준 캔버스 1920×1080, 아래 좌표는 좌상단 원점의 x/y/w/h. 외곽 안전 여백 48. 간격 단위 8, 기본 내부 패딩 24. Unity RectTransform에서는 원점 변환이 필요하다. 16:9 외 비율은 중앙 컨테이너 폭을 제한하고 좌우 HUD는 각 코너에 앵커한다.

UI 장식은 2px 기준으로 제작하고 정수 배율로 표시. 본문은 그림에 굽지 않고 실제 로컬라이즈 폰트를 사용한다. 본문 28, 설명 26, 보조 24, 제목 40, 수치 32px를 시작점으로 삼는다. 한국어/일본어 줄바꿈과 1280×720 축소 시 실기 확인이 필요하다. 본문을 자동 축소해 해결하지 않는다.

| 역할 | 제안 색 | 규칙 |
|---|---|---|
| 패널 | #17212B / #263442 | 어두운 불투명 면, 본문 뒤 질감 최소 |
| 기본 테두리 | #637583 | 얇은 가장자리 |
| 본문 / 보조 | #E7E0CE / #ABB8C0 | 명도 차이로 우선순위 |
| 선택 | #E7E0CE | 밝은 이중 외곽선+좌우 홈+선택 표식 |
| 장식 금속 | #96806A | 통화/희귀도와 혼동하지 않는 저채도 |
| HP / 위험 | #B94B53 | HP 라벨/수치와 병행 |

시너지/희귀도 색은 기존 게임 표시 SoT를 사용한다. 위 표로 덮어쓰지 않는다. 폼마다 새 전용 색을 만들지 않는다.

## 버튼·슬롯 상태

- 기본: 어두운 면+얇은 테두리. Hover: 면 한 단계 밝게. 패드 선택: 밝은 외곽선+좌우 홈+선택 표식. 색 변화만으로 구분하지 않는다.
- 눌림: 2px 안쪽으로 이동, 클릭 완료 뒤 복원. 비활성: 대비를 낮추되 이유 문구 유지. 구매 불가를 선택 불가와 혼동하지 않는다.
- 쿨다운: 아이콘 위 별도 게이지 레이어. 이미지에 수치/게이지를 굽지 않는다. 현재 Presenter의 진행 방향을 확인 후 연결한다.
- 선택 장식은 별도 Image, Raycast Target=false. 실제 Button의 Submit과 첫 포커스 규칙을 유지한다. 원시 A/Enter 처리 추가 금지.
- 화면 열림 입력의 중복 확정 방지, 저장/설정/도감 우선권, 닫은 프레임 보호, 자기 선택 정리 등 이전 구현 계약을 보존한다.
- 필수 선택 화면에 디자인 편의로 취소를 추가하지 않는다. 스킬 교체 취소와 폼 교체 취소는 기존 동작이 다르므로 공통 함수로 합치지 않는다.

## Claude 구현 인계 순서

1. HUD 한 화면: HealthBar/FormSlot/SkillSlot/GoldCounter와 실제 빌더의 소유권을 먼저 조사. 기존 이벤트/데이터 연결을 유지하며 배치만 변경.
2. 드래프트와 경로: 카드 프레임/상태 표식 적용, 기존 상세 설명과 경로 패드 Navigation 보존.
3. 대화·상점·제단·교체: 공통 스킨만 공유하고 각각의 선택/취소/정산 계약은 유지.
4. 도감·설정·결과·타이틀: 레이아웃별 작은 작업으로 나눠 인계. 게임 전체 동시 교체 금지.

각 단계는 허용 파일을 실제 조사 후 확정하는 별도 task 계약을 만든다. 이번 요청은 디자인·이미지 제작이므로 게임 코드 적용은 시작하지 않는다.

## 인수 기준

- 미술: Stage1 v1과 픽셀 면/청회색 재질 연결, 과한 성전·해골·발광 장식 없음.
- UX: 폼 교체 준비/스킬 쿨다운/HP가 서로 다른 위치·표식으로 보임. 선택 카드가 정지 화면에서도 명확.
- 구현: 이미지 텍스트 대신 실제 CSV/바인딩/잔액/아이콘 사용. 데이터 없는 통계/스킬 효과 생성 금지.
- 사용자 실기: 720p/1080p, 한국어/영어/일본어, 패드/마우스, 긴 설명, 0잔액, 비활성 항목, 상위 창, 다음 방 진행.
- 현재 상태: 설계 제안. 실제 에셋 임포트·Unity 적용·실기 검증 미완료.
