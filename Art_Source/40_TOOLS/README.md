# 40_TOOLS — 도구 어댑터

> 🔥 **버리는 층이다.** 도구가 바뀌면 이 폴더만 새로 쓰고 `00~30`은 그대로 간다.
> 그러라고 나눈 것이다 — 넉 달에 도구가 세 번 바뀌었고, 그때마다 정체성 파일까지 같이 죽었다.

## 현행

| 폴더 | 도구 | 상태 |
|---|---|---|
| `pixellab/` | PixelLab **Pro / v2** (`/generate-image-v2` — `style_image` 유무로 앵커·파생을 가른다) | ✅ 현행 (2026-09-06 결정) |

> 🔑 **같은 날 두 번 바뀌었다.** 처음엔 legacy(`pixflux` 앵커 → `bitforge` 파생)로 잡았다가
> Pro/v2 로 옮겼다 — *"legacy로 작업했다가 나중에 또 바꾸면 그 시간이 낭비"*라는 판단이다.
>
> 🔴 **그 전환에서 이 폴더의 존재 이유가 처음으로 증명됐다.** 엔드포인트를 통째로 갈았는데
> `00_SOURCE`·`10_BIBLE`·`20_SUBJECTS`·`30_BLOCKS`는 **한 글자도 안 바뀌었다.**
> 단, 그러려면 **집행 장치가 이 층에 있으면 안 된다** — 아래 표의 첫 줄이 그 교훈이다.

과거 도구의 문법 메모는 `_legacy/gen2-novelai-v5/prompts/02_rules.txt`(NovelAI 가중치·Undesired Content
괄호 반전)와 `_legacy/gen3-pixellab/prompts_env/02_params.txt`(PixelLab enum·면적 제한)에 남아 있다.
**다시 그 도구로 갈 일이 생기면 거기서 꺼내 온다.**

## 프로필이 담아야 할 것

도구를 바꿀 때 **매번 다시 알아내야 했던 것들**이다. 적어 두면 다음엔 안 알아낸다.

| 항목 | 왜 필요한가 |
|---|---|
| 문구 문법 | 태그 나열형인가 문장형인가. 가중치 표기 |
| **문구 길이 한계** | PixelLab은 20~35 단어를 넘기면 희석된다. NovelAI는 안 그렇다 |
| ~~**강제 장치 유무**~~ | 🔴 **이 줄은 이제 도구에 물을 것이 아니다.** 팔레트 강제를 `Tools/ArtPipeline/enforce_palette.py`로 옮겼다 — 도구 무관. **바이블의 핵심 장치를 버리는 층의 기능에 걸어 둔 것이 설계 실수였다** |
| 부정 프롬프트 유효성 | 모델마다 다르고 **아예 없을 수도 있다**(v2 Pro). 없으면 판정으로 막는다 |
| 스타일 고정 수단 | `style_image` + 강도. 없으면 텍스트로만 붙들어야 한다 — **gen2가 거기서 죽었다** |
| 파라미터 칸이 몇 개나 있나 | 🆕 v2 Pro는 `outline`/`shading`/`detail`/`view`가 **전부 없다**. 그 지정을 문구로 내려야 하고 **문구 예산을 먹는다** |
| 해상도·면적 제한 | 티어마다 다르다. ⚠️ **제한이 풀리면 값이 자동으로 좋아지는 게 아니다** — 픽셀 밀도는 우리가 정한다 |
| 알파 산출 | 직접 내는가, 크로마키가 필요한가 |
| 세션 규약 | 🔴 **한 씬은 한 세션에서 끝낸다** — 날짜를 넘기면 같은 설정이어도 색온도가 갈린다 |
