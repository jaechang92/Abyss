> **이 폴더는 버리는 층이다** — 도구가 바뀌면 여기만 새로 쓴다. 파라미터 실물은 `params.txt`.

## 0. 왜 Pro 로 갔나 — 그리고 무엇을 내줬나

**결정 (사용자, 2026-09-06)**: *"Legacy로 작업했을 때 나중에 변경이 발생하면 또다시 낭비되는 시간이 싫다."*

v2 라인업에서 **화풍 고정 수단(`style_image`)이 있는 비-legacy 경로는 Pro뿐이다.**
`pixen`은 스타일 참조가 아예 없어서 정체성을 문자열로만 붙들게 되는데, **그건 gen2(NovelAI)가 죽은 자리다.**
그러므로 "legacy를 피하면서 정체성도 지킨다"는 조건에서 Pro는 유일한 답이다.

### 내준 것 셋 — 전부 보상 경로가 있다

| 잃은 칸 | 무엇을 하던 칸인가 | 어떻게 메우나 |
|---|---|---|
| `color_image` | 팔레트 **강제** | 🔑 **후처리로 이관** — `Tools/ArtPipeline/enforce_palette.py`. 도구 무관 |
| `negative_description` | 안 그릴 것 지정 | **판정으로** — 조립본 `.md`의 체크리스트. 원래도 `pixflux`에선 안 먹던 칸이다 |
| `outline` / `shading` / `detail` | 선·명암·밀도 지정 | **문구로 흡수** — `params.txt [STYLE-WORDS]`가 영문 어구로 갖고 있다 |

> 🔴 **`color_image`를 잃은 것이 오히려 설계를 고쳤다.**
> 바이블의 핵심 장치가 *버리기로 한 층의 기능*에 걸려 있었다 — 도구가 바뀌면 규약이 같이 죽는 구조였고,
> 이 재작성이 고치려던 바로 그 병이었다. 자세한 것은 `10_BIBLE/04-palette.md` 머리말.

### 알면서 어기는 것 하나 🔴

PixelLab 자신의 라우팅 가이드가 **우리 용도를 콕 집어 반대한다**:

> *"Pro is not worth its ~12× cost for scenes/backdrops/parallax."*
> *"subject-less backdrops → PixFlux (beats Pixen)."*

우리가 지금 하는 것이 정확히 **인물 없는 배경 8씬**이다. 그럼에도 Pro로 가는 이유는 위의 하나 —
**legacy 재이관 비용을 안 치르기로 했다.** 비용 12배는 그 값으로 받아들인 것이다.

⚠️ **이 판단이 뒤집힐 조건**: stage1 앵커에서 Pro 산출물이 화질·일관성에서 별 차이가 없으면,
후처리 팔레트가 이미 섰으므로 **`pixflux`로 되돌리는 비용은 이 폴더 하나**다. 그때 다시 잰다.

## 1. 요약

| 항목 | PixelLab Pro (v2) |
|---|---|
| 문구 문법 | **문장형.** 태그 나열이 아니다 |
| 문구 길이 한계 | 🔴 **대략 20~35 단어.** 길면 서로 희석되어 아무것도 안 걸린다 |
| 가중치 표기 | 없다 |
| **스타일 고정** | ✅ `style_image` (+ `reference_images` 최대 4장) |
| **팔레트 강제** | ❌ **엔드포인트에 없다** → 후처리(`enforce_palette.py`)가 집행한다 |
| 부정 프롬프트 | ❌ 없다 → **판정으로 막는다** |
| `outline`/`shading`/`detail` | ❌ 없다 → **문구로 흡수** |
| 알파 | ⚠️ **미확인** — `/generate-image-v2`에 `no_background`가 문서에 없다. 없으면 `chroma_cutout.py` |
| 크기 | 최소 16x16 · 최대 512x512(정사각) / 688x384(16:9) |
| `seed` | ⚠️ **미확인** (`/generate-with-style-v2`에는 있다) |
| 타일셋 | ✅ **웹 도구 Create Tileset** — API 아님, 이 전환의 영향을 안 받는다 |

### 🔴 크기에 대해 — 제약이 선택으로 바뀌었다

`160x96`은 원래 **무료 티어 면적 제한(200x200)** 때문에 고른 값이다. Pro에는 그 제한이 없다.

**그런데 숫자는 그대로 둔다.** 픽셀 밀도는 이제 도구가 정하는 것이 아니라 **우리가 정하는 것**이고,
688x384로 뽑으면 픽셀 아트가 아니라 "픽셀처럼 생긴 일러스트"가 된다.

📌 **제약이 사라졌는데 값을 안 고치면, 다음 사람은 그게 아직 제약인 줄 안다.** 그래서 적어 둔다 —
**이 숫자는 이제 한계가 아니라 판단이다.**

## 2. 두 엔드포인트

| | `/generate-image-v2` | `/generate-with-style-v2` |
|---|---|---|
| 용도 | **앵커 + 파생 전부** (현행) | 후보 — 프롭 묶음 생성 |
| `description` | 필수 | 필수 |
| `image_size` | ✅ `{width, height}` **객체다** (문자열 아님) | ❌ 스타일 이미지에서 유도 |
| `style_image` | 선택 1장 | `style_images` 1~4장 **필수** |
| `reference_images` | 최대 4장 | — |
| `no_background` | ⚠️ 미확인 | ✅ 있다 |
| `seed` | ⚠️ 미확인 | ✅ 있다 |

> 💡 **왜 `/generate-image-v2` 하나로 가나** — 필드를 스펙에서 확인한 쪽이 이것뿐이다.
> `/generate-with-style-v2`는 출력 크기를 스타일 이미지에서 **유도**하는데(최대 512, 정사각),
> 우리 배경은 가로로 긴 판이라 그 규칙이 안 맞는다. 다만 **프롭 묶음**(`COUNT>1`, 알파 필요, 정사각)에는
> 오히려 맞을 수 있다 — 격자로 여러 장을 한 번에 준다. **첫 실호출 때 확인하고 정한다.**

> 🔴 **앵커에서 인물·광원·이끼가 나오면 문구를 손보지 말고 다시 뽑는다.**
> 이제 부정 프롬프트 칸 자체가 없다. **막는 것은 프롬프트가 아니라 판정이다**
> (`10_BIBLE/03-light.md §5`).

## 3. 순서 — 어기면 전부 다시 뽑는다

```
① 팔레트를 굽는다        50_BUILD/make_palettes.py   →  palettes/<scene>.png
② 조립한다               50_BUILD/build.py           →  assembled/
③ 앵커를 여러 장 뽑는다   /generate-image-v2          (bg_mid, style_image 없이)
④ 사람이 한 장 고른다     →  anchors/<scene>.png
⑤ 나머지를 뽑는다         /generate-image-v2 + style_image = 그 앵커
⑥ 🆕 팔레트를 집행한다    Tools/ArtPipeline/enforce_palette.py
⑦ 타일셋만 웹 도구로     Create Tileset
⑧ 한 씬을 Unity 재생까지 관통한다
⑨ 나머지 씬 반복
```

🔴 **①이 먼저인 이유가 바뀌었다.** 예전에는 `color_image`가 강제라서였다. 이제는
**팔레트가 앵커를 고르는 판정 기준**이기 때문이다 — 기준 없이 뽑은 앵커는 무엇과 비교해 고를지가 없고,
그 한 장이 그 씬 전부의 화풍을 결정한다. **결론은 같고 근거만 바뀌었다.**

🔴 **⑥은 건너뛸 수 없다.** 생성 단계에 강제 장치가 없으므로 **여기가 P1~P5가 지켜지는 유일한 자리**다.

🔴 **⑧을 건너뛰지 않는다.** 8씬 130장을 뽑은 뒤 임포트·슬라이스·패럴랙스 문제를 발견하면 전부 다시 한다.
gen2·gen3가 둘 다 이 줄을 적어 두고도 지키지 못했다.

## 4. 세션 규약 🔴 — Pro 로 오면서 더 중요해졌다

**한 씬의 레이어들은 반드시 한 세션 안에서 끝낸다.**
패럴랙스는 여러 장이 겹쳐 보이는 구조라 색온도 차이가 그대로 층으로 드러난다.
날짜를 넘겨 이어 뽑으면 같은 설정이어도 갈린다 — gen2·gen3가 둘 다 실측으로 적어 둔 것이다.

> 🔴 **`seed`가 있는지 확인이 안 됐다.** legacy에서는 씬 안에서 seed를 고정해 흔들림을 잡았는데,
> `/generate-image-v2`에 그 칸이 있는지 문서에서 확인하지 못했다.
> **없다면 이 규약이 권고가 아니라 유일한 방어선이 된다.** 첫 실호출 때 확인할 것.

`seed`가 있다면 한 씬 안에서 고정한다. **예외는 프롭 하나** — 고정하면 다섯 개가 전부 닮은 물건이 된다.

## 5. Unity 임포트

| 대상 | 설정 |
|---|---|
| 배경 레이어 | Sprite(Single). 패럴랙스 계수는 먼 것이 덜 움직인다 |
| 타일셋 | Sprite(Multiple) → 격자 슬라이스 → Tile Palette |
| 발판·프롭 | Sprite(Single), 피벗 **Bottom** |

전부 **Filter Mode: Point (no filter)** · **Compression: None**.
픽셀 아트에 Bilinear가 걸리면 확대할 때 뭉개진다.

## 6. 미확인 목록 🔴 — 첫 실호출 때 채운다

계정이 필요해 **사람이 확인해야 하는 것들**이다. 값을 지어내 채우지 않는다.

```
① /generate-image-v2 에 no_background 가 있는가   → 없으면 프롭은 chroma_cutout.py
② /generate-image-v2 에 seed 가 있는가            → 없으면 §4가 유일한 방어선
③ style_image 의 적용 강도를 조절하는 칸이 있는가  → legacy 의 style_strength 대응물
④ image_size 가 정말 {width,height} 객체인가       → build.py 가 그 모양으로 낸다
⑤ 160x96 처럼 작고 가로로 긴 크기를 받는가        → 최소 16x16 이라 될 것으로 본다
⑥ 1회 생성 비용 (legacy 대비 실제 배수)
```
