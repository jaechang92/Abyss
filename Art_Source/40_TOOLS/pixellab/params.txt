[ANCHOR]

#    v2 는 **같은 엔드포인트에 style_image 유무로만 갈린다.** 규약은 그대로고 수단만 단순해졌다.

[STYLE-WORDS]
# 🆕 v2 에는 outline/shading/detail/view 칸이 없다. 그 지정을 **문구로 내린다.**
#
# 🔑 **거의 항등 사상이다. 그게 맞다.**
#    legacy 의 enum 값(`lineless` `flat shading` `low detail` `side view`)은
#    애초에 영어 프롬프트 어휘 그대로였다. 칸에서 문구로 자리만 옮기면 된다.
#
# ⚠️ 처음에는 설명형으로 길게 썼다가 되돌렸다 —
#    `lineless, edges read by value not by line` 식으로 쓰면 네 필드가 20 단어가 되어
#    **[WORD-BUDGET] 40 을 스타일 지정만으로 절반 먹는다.** 파트 문구가 그만큼 밀리고,
#    PixelLab 은 문구가 길면 서로 희석되는 모델이다. 정체성을 말할 자리를 뺏으면 안 된다.
#
# 💡 그래도 이 표가 있어야 하는 이유 셋:
#      ① 이 값들이 이제 **필드가 아니라 문구**라는 사실이 여기 적혀 있다
#      ② 모델이 못 알아들으면 **고칠 곳이 여기 한 곳**이다
#      ③ 오타를 build.py 가 잡는다 — 없는 키는 경고가 뜬다.
#         (조용히 빠지면 "안 실었다"와 "모델이 무시했다"를 구분할 수 없다)
# 🔴 값은 **짧은 토큰 하나로 통일**한다 (`medium`, `low`, `high` — `medium detail` 아님).
#    첫 빌드에서 파트 파일 5줄이 전체 enum 형(`flat shading`·`highly detailed`)을 쓰고 있어
#    어휘가 갈려 있었고, build.py 경고가 그것을 잡았다. 둘 다 받게 하면 파편화가 남는다.
#    ⚠️ 새 값을 쓸 때는 반드시 여기에도 줄을 추가할 것. 없으면 경고가 뜬다(조용히 안 빠진다).
outline_lineless = lineless
outline_selective = selective outline
shading_flat = flat shading
shading_basic = basic shading
shading_medium = medium shading
detail_low = low detail
detail_medium = medium detail
detail_high = highly detailed
view_side = side view
