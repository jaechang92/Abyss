# ══════════════════════════════════════════════════════════════
# 지면 타일셋 — 스테이지의 바닥. PixelLab **Create Tileset** 도구 (API 아님, 웹 도구)
#
# 🔑 이게 PixelLab 을 쓰는 가장 큰 이유다.
#    Wang 타일셋을 만들어 **dual-grid 15-tileset / 3x3 형식으로 export** 할 수 있고,
#    그게 Unity Tilemap 에 그대로 들어간다. 심리스를 손으로 맞출 필요가 없다.
#    NovelAI 로는 이걸 할 방법이 아예 없었다.
#
# 입력은 셋이다:
#    inner       안쪽 재질 — 밟는 땅의 속
#    transition  경계 — 땅의 윗면, 플레이어가 서는 자리
#    outer       바깥 재질 — 땅이 아닌 것
#
# 🔴 재질은 씬의 [MATERIAL] 이 아니라 [GROUND-MATERIAL] 을 쓴다.
#    [MATERIAL] 은 배경(160x96)용이라 "toppled pillars(쓰러진 기둥)"·"rotted banners"
#    같은 **물건**이 섞여 있다. 배경에서는 그게 풍경이지만 32px 타일 안에서는
#    기둥 하나가 타일 전체를 차지하고, 바닥을 깔 때마다 같은 기둥이 반복된다.
#    **심리스가 눈에 보이는 순간 타일은 죽는다.** 타일에 들어가도 되는 것은
#    면으로 무한히 반복되는 재질뿐이다.
#    build.py 가 [USE-SCENE] 에 적힌 순서로 먼저 있는 블록을 쓴다(없으면 MATERIAL 폴백).
#
# 🔴 outer 는 씬이 덮을 수 있다 — 씬 파일에 [TILE-OUTER] 가 있으면 그쪽이 이긴다.
#    대부분은 "어두운 허공"이지만 스테이지 5(심연의 핵)는 바닥 밖이
#    허공조차 아닌 무(無)다. (예전 주석은 build.py 가 씬에서 가져다 쓴다고 적혀
#    있었지만 실제 코드는 파트의 [OUTER] 만 봤다 — 이제 실제로 그렇게 동작한다)
#
# ⚠️ transition 이 이 게임에서 가장 중요한 한 줄이다 — **플레이어가 서는 면**이다.
#    Unity Tilemap 콜라이더는 격자 칸 경계라 윗면이 울퉁불퉁하게 그려지면
#    보이는 바닥과 실제로 밟히는 높이가 어긋나 캐릭터가 떠 있거나 파묻혀 보인다.
#    그래서 벽(tileset_wall)은 broken edge 를 쓰지만 **지면은 평평한 한 줄**을 요구한다.
#    tile_platform.txt 의 "윗면이 평평해야 한다"와 같은 이유이고, 같은 실패다.
#    border_jitter = medium 인 채로도 울퉁불퉁하면 도구 UI 에서 한 단계 낮춘다.
#
# ⚠️ tile_size 는 16 또는 32 만 된다. transition_size 는 경계 높이 —
#    0 이면 평평하고, 값이 크면 땅 위에 벽이 선다. 플랫포머는 1 이 무난하다.
# ══════════════════════════════════════════════════════════════

[KIND] tileset
[PARAMS] PARAMS-TILESET
[USE-SCENE] GROUND-MATERIAL, MATERIAL
[COUNT] 1

[INNER]
# 캐릭터 뒤로 화면에서 가장 넓게 깔리는 면이다. 조용할수록 캐릭터가 산다.
# "nothing lying on it" 은 금지어가 아니라 서술이다 — 이 면 위에는 물건이 없다.
solid packed ground, one even repeating material, nothing lying on it

[TRANSITION]
# 밟는 면. "평평함"과 "여기서 땅이 끝난다"가 동시에 읽혀야 한다.
# 아래보다 밝게 두는 것은 연출이 아니라 가독성이다 — 서는 자리가 선으로 보여야 한다.
the flat level top surface, one straight walkable line,
worn smooth, slightly lighter than the ground below

[OUTER]
dark empty air
