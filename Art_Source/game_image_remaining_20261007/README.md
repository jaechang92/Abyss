## 선택과 보완

40종 + 보완 5회 = PNG 45개를 보관한다. sky/far 두 종/상인 두 종은 v2 선택, 이전 v1은 폐기하지 않고 보관한다. sky-v1의 과도한 건축, Stage2 far-v1의 불투명 하늘, Stage3 far-v1의 가까운 구조물, 초상 두 종의 끝단 접촉을 수정했다. manifest의 선택 경로를 사용하고 폴더에서 첫 파일을 임의 선택하지 않는다.

Stage2는 녹슨 철·분말 적색·낮은 구름, Stage3는 하늘 없이 창백한 회색 석재·마른 녹이다. Stage2 순서는 sky-v2 → 투명 far-v2 → mid-v1 → near-v1. Stage3는 불투명 far-v2 → mid-v1 → near-v1. 중경·근경의 캔버스 가장자리 접촉은 양쪽 프레이밍을 위한 것이며 대표방 배치에서 확인한다. Stage3 바닥은 끝단 접촉이 있어 반복 연결·외곽 여백·상면 기준을 확인해야 한다.

## Claude 구현 인계

이미지 제작·파일 대조까지 진행했다. 이번 작업에서 게임 코드·씬·데이터 참조는 변경하지 않았으며 런타임 연결은 미진행이다. 병행 작업의 R1/C1 코드·씬과 튜토리얼 이미지, 기존 미커밋 변경은 보존했다. 자동 구현 배정을 새로 시작하지 않는다.

1. 필요한 이미지부터 명시적 Sprite 참조로 연결한다. `Assets/Art/UI` 아래 준비본이므로 Resources.Load 자동 경로로 가정하지 않는다. 불러오기 실패 시 기존 표현을 유지한다.
2. 고해상도 제작 원본을 그대로 월드에 배치하면 지나치게 커질 수 있다. 캐릭터 대비 목표 크기·정수 픽셀 배율·실제 아트 영역을 먼저 정한다. 바닥의 윗면과 기존 충돌체 높이를 일치시키되 충돌·이동 수치를 아트 때문에 바꾸지 않는다.
3. 상태 쌍은 동일 캔버스이고 원본을 참조해 제작했지만 픽셀 좌표까지 완전히 동일하지 않다. QA의 bbox를 참고해 공통 바닥축·pivot·규모를 맞춘 후 화면에서 전환 흔들림을 확인한다. 생성된 외곽의 부드러운 그림자/반투명 테두리가 어두운 배경에서 번지지 않는지도 확인한다.
4. 기존 이벤트의 선택·대가·보상·취소·완료 신호를 그대로 사용한다. 열린 문/빈 받침 이미지가 보상이나 다음 방 이동을 자동 실행해서는 안 된다. 샘은 사용 후에도 물이 남는다.
5. VFX는 애니메이션 시트가 아니다. 기존 타격 시점·수명·히트박스·소리·피드백에 연결한다. 일반 피격/가드/저스트 가드/치명타의 실루엣 차이를 플레이 중 비교한다.
6. 선택 괄호 원본은 왼쪽으로 열린 오른쪽용 괄호다. 왼쪽용은 표시 단계에서 수평 반전한다. 키 문자·패드 바인딩은 빈 프레임 위에 별도 표시하며 작은 크기의 프레임 두께와 읽힘을 확인한다.
7. Frost/Soul은 예약 아이콘이다. 실제 SoulReclaim의 Abyss 태그를 녹색 Soul 아이콘으로 바꾸지 않는다. Stage4·5의 완성 룸이나 새 적 애니메이션은 현재 데이터가 확정되지 않아 이 묶음에서 임의 제작하지 않았다.
