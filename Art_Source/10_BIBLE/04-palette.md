# 04 — 색

> **색은 폼을 가리키지 않는다. 색은 시너지 축을 가리킨다.**
> 근거: `00_SOURCE/quotes-color.md` · 결정 2026-09-06 (사용자) · 작성 2026-09-06

팔레트는 **부탁이 아니라 강제**다. 그러므로 팔레트를 무엇으로 굽느냐가
이 파이프라인에서 판정이 끝나는 자리다 — **색을 고르는 순간 결정된다.**

> 🔴 **집행 지점 변경 (2026-09-06 · 이 문단이 원래 틀렸다)**
>
> 이 문서는 원래 *"PixelLab의 `color_image`는 부탁이 아니라 명령이다"*로 시작했다.
> **설계 실수였다.** `color_image`는 PixelLab의 **legacy 엔드포인트에만 있는 칸**이고,
> `40_TOOLS/`는 애초에 **버리는 층**으로 만든 폴더다.
> 즉 바이블의 핵심 장치를 버리기로 한 층의 기능에 걸어 뒀다 —
> **도구가 네 번째로 바뀌면 P1~P5가 같이 죽는 구조**이고, 이 재작성이 고치려던 바로 그 병이다.
>
> 집행을 **생성에서 후처리로** 옮겼다:
>
> ```
> 생성 (도구가 무엇이든)  →  Tools/ArtPipeline/enforce_palette.py  →  P1~P5 보장
> ```
>
> 픽셀 아트의 표준 공정이고 도구에 안 묶인다. `color_image` 같은 칸이 있는 모델이면
> 그쪽에도 넣는다 — 다만 **집행의 권한은 후처리에 있다.** 생성 단계의 팔레트 지정은
> 이제 강제가 아니라 **적중률을 올리는 보조 수단**이다.
>
> 🔑 **얻은 것이 하나 더 있다 — 강제의 대가를 잴 수 있게 됐다.**
> `color_image`는 결과만 주고 *"얼마나 끌어왔는지"*를 안 알려준다. 후처리는 그걸 잰다
> (ΔE·쓰인 램프 단수·뭉침). **팔레트에서 한참 벗어난 그림을 억지로 스냅하면 색 검사는
> 통과하는데 그림이 뭉개지고, 그 결과물은 조용하다.** 그래서 거리가 크면 고쳐 붙이지 않고
> 다시 뽑는다 — **막는 것은 강제가 아니라 판정이다**(`03-light.md §5`와 같은 태도).

## 1. 2026-09-06 결정 — 색을 폼에서 뗐다

### 무엇이 문제였나

**들은 것**: 폼은 M1 2 → M2 4 → M3 6 → **M4 8~10** 으로 는다 (`08-content-roadmap.md:13`).
**들은 것**: 시너지 축은 6종으로 고정이고, `SynergyAxis.cs` 가 색까지 포함한 표시 규약 SoT다.

폼당 색 하나 방식은 **4번째 폼에서 이미 깨졌다**:

> 투척사는 **설정상 심연 축이지만** 궁수와 같은 보라를 쓰면 구분이 안 되어 **청록으로 갈랐다.**
> — `_legacy/gen1-web-imagegen/GUIDELINE.md §6`

그리고 두 색이 실제로 **완전히 겹쳐 있었다**:

| 축 (`SynergyAxis.cs`) | 폼 액센트 (`GUIDELINE.md §6`) | |
|---|---|---|
| `abyss` `#A36BF5` | 공허 궁수 `#A36BF5` | 🔴 동일 |
| `guard` `#FFCC52` | 고대 방패병 `#FFCC52` | 🔴 동일 |
| `fire` `#FF752E` | 암흑 검사 `#EE773D` | 거의 동일 |

**하나의 색이 「어느 폼인가」와 「어느 축인가」를 동시에 말하고 있었다.**
그런데 축은 6에서 고정이고 폼은 10까지 는다 — **모자랄 때마다 축에서 떼어 오게 되어 있었다.**

## 2. 세 레지스터

`13-novel-game-glossary.md §3`이 「어비스(소설) vs 심연(게임)」을 **레지스터 차이**로 해소한 것과 같은 수법이다.
모순이 아니라 **사는 자리가 다르다.**

### ① 월드 색 — 소설 규약

```
무채 램프    검정 ── 잿빛(탈색된) ── 흰(비어 있음)     전 씬 공통
층 강조      씬마다 하나. 발광하지 않는다
지상 전용    초록 — 어비스 안에는 없다
```

| # | 규약 | 표시 | 근거 |
|---|---|---|---|
| P1 | **회색은 순수 무채가 아니다.** 잔여 채도를 남긴다 | **잰 것** | *"물에 오래 있어서 다 빠졌다"* `3권/30:40` — 회색은 색이 **빠진 결과**다 |
| P2 | **씬은 잔여 색상으로 갈린다.** 명도 구성이 같아도 남은 색이 다르면 다른 데로 읽힌다 | **지어낸 것** | P1에서 파생. 무채 규율을 지키면서 씬을 가르는 유일한 수단 |
| P3 | **층 강조는 하나뿐이고 발광하지 않는다** | **잰 것** | 붉음 = 녹 = 산화 `1권/10:19,58`·`29:310` |
| P4 | **순검정·순백을 램프 양끝에 쓰지 않는다** | **잰 것** | 좁은 대비 (→ `03-light` L3) |
| P5 | **어비스 안에 초록을 쓰지 않는다** | **잰 것** | 초록 4회, **전부 지상·시엔** `1권/01:68`·`14:290` |
| P6 | **흰색은 밝음이 아니라 여백이다.** 강조색으로 쓰지 않는다 | **잰 것** | *"아무것도 없는 흰 자리"* `1권/03:107` |

**P1의 실무 형태 (지어낸 것)**: 회색 램프의 채도를 0이 아니라 **낮게 남긴다.**
값은 앵커 실측 후 정한다 — 지금 숫자를 박으면 재지 않고 정하는 것이 된다.

**P1·P4의 명시적 예외** — 첫 추락자의 씬:

> `hidden_first_fallen` 은 **완전 무채색 + 단 하나의 색**이다. 남은 하나는 **벽에 새긴 자국에만** 쓴다 — 이름만 색을 가진다.
> — `_legacy/gen3-pixellab/prompts_env/palettes/_palettes.txt`

**이름을 잃고 아래로 간 자**라서 색이 없다. 🔑 **무채색이 연출이 아니라 설정인 유일한 씬**이므로 예외로 남긴다.
gen3에서 살릴 값이 있는 판단이었다.

### ③ 폼 구분 — 색이 아니다

색을 뺀 자리에 들어가는 것들. **전부 소설이 준 어휘다.**

| 축 | 소설 근거 |
|---|---|
| **실루엣 도형** | 세로선(대검) · 곡선(활) · 사각(탑실드) · 삼각(퍼지는 망토) — gen1이 정해 둔 것 (**들은 것**) |
| **손** | 굽어 안 펴지는 손 / 숯에 물든 검은 손 / 성한 손 — `3권/14`·`16`·`23` (**잰 것**) |
| **걸음** | 왼발이 밖으로 도는 걸음 — `3권/13` (**잰 것**) |
| **맨 것** | 붉은 실이 두 번 감기고 한 번 묶임 — `3권/12:11` (**잰 것**) |
| **자국** | 닳은 자리 · 발자국 (`자국` 132회) (**잰 것**) |

> 🔑 **소설 자체가 얼굴로 사람을 안 가른다.** 하란은 자기를 세 번 만나면서 얼굴이 아니라
> 손과 걸음으로 확인한다. **폼 구분을 색에서 형태로 옮기는 것은 아트 편의가 아니라 원작의 방법이다.**

⚠️ 폼 몸 색은 여전히 필요하다 — 갑옷·천의 색이다. 그것은 **월드 램프 안에서** 고른다.
폼끼리는 램프 위치(어두운 쪽/밝은 쪽)와 실루엣으로 갈리지, 색상으로 갈리지 않는다. → `08-silhouette.md`

## 3. 씬 팔레트를 굽는 절차

```
① 씬의 정체 한 줄을 정한다        → 20_SUBJECTS/scenes/<씬>.md
② 무채 램프 7~9단 + 층 강조 2~4색 → 합계 9~13색
③ S3 검사 — 신호 6색과 명도/채도에서 갈리는가
④ P5 검사 — 초록이 없는가 (지상 씬 제외)
⑤ PNG 로 굽는다                    → 50_BUILD/make_palettes.py
⑥ 앵커를 뽑고 03-light §5 체크리스트로 판정
⑦ 가장자리의 흰 거터를 뗀다        → Tools/ArtPipeline/enforce_palette.py --crop-gutter
⑧ 집행한다                         → Tools/ArtPipeline/enforce_palette.py (같은 호출)
```

**⑧이 강제가 일어나는 유일한 자리다.** 생성 도구가 무엇이든 여기를 지나야 P1~P5가 보장된다.
그리고 이 단계가 **⑥의 판정을 숫자로 거든다** — 옮긴 거리(ΔE)가 크면 그 앵커는 팔레트를
안 따른 것이므로, 스냅해서 쓰지 말고 다시 뽑는다.

```
python Tools/ArtPipeline/enforce_palette.py raw/*.png --scene stage1_rift_entrance --crop-gutter
python Tools/ArtPipeline/enforce_palette.py raw/*.png --scene stage1_rift_entrance --check --crop-gutter   # 재기만
```

🔴 **⑦을 먼저 하지 않으면 ⑧의 숫자를 믿을 수 없다.** 생성기가 준 그림에 순백 테두리가
딸려 오는 일이 있는데, 그것이 붙은 채로 재면 ΔE·「쓰인 색」·뭉침이 전부 그 순백까지 재고 나온다
— 실측에서 ΔE 0.8 / 8단이 자른 뒤 0.0 / 7단으로 바뀌었다. `--crop-gutter` 를 안 켜도 붙어
있으면 알리므로, **경고가 뜨면 켜고 다시 돌린다.** 두께가 매번 달라 고정 픽셀로는 못 자른다.

⚠️ **ΔE 0이 합격이 아니다.** 이미 팔레트 색만 쓴 그림은 거리가 0으로 나오는데,
램프 10단 중 2단만 쓴 납작한 그림도 마찬가지로 0이다. **「쓰인 색」 줄을 같이 본다.**

**판정은 눈이 아니라 숫자로도 한다** — `Tools/ArtPipeline/measure_consistency.py`.
🔴 **방향이 둘로 갈린다:**

| 재는 것 | 좋은 방향 | 왜 |
|---|---|---|
| 한 씬의 레이어들 사이 팔레트 겹침 | **높다** | 네 장이 겹쳐 보이므로 색온도가 갈리면 층으로 드러난다 |
| 씬과 씬 사이 팔레트 겹침 | **낮다** | 다른 세계의 밑바닥이므로 |
| 씬 팔레트 ↔ 신호 6색 | **낮다** | S3 |

기준값은 웹 image_gen 시절 실측(폼 내부 81.7~90.4%)이라 **PixelLab 기준으로 다시 잰다.**
지금 숫자를 옮겨 적으면 안 재고 정하는 것이 된다.

## 5-A. ΔE 기준값 — 숫자가 아니라 구조로 답했다 (2026-09-10)

170장이 쌓인 뒤 재서 알아낸 것 둘이다.

**① 선이 관측 최대보다 위에 있어 한 번도 안 걸렸다.**

```
현재 선     평균 12.0 / 상위5% 28.0
관측 최대   평균  9.7 / 상위5% 24.4
```

「지어낸 값이다」라는 옛 서술보다 이쪽이 큰 문제다 — **있는 줄 알았던 방어선이 없었다.**

**② 한 선으로 못 자른다. 두 분포가 겹치지 않는다.**

```
파생 (style_image 있음)      평균 0.3 ~  6.2    상위5% 3.7 ~ 24.4   25장
앵커 (style_image 없음)      평균 4.4 ~ 10.1                        20장
타일셋 (style 칸 자체 없음)   평균 3.9 ~  9.7    상위5% 6.6 ~ 13.1    4장
```

**파생의 최악(6.2)이 타일셋의 최선(9.2)보다 낮다.** 붙들 수단이 다르면 결과 분포가 다르다 —
파생에 맞춘 선은 타일셋을 전부 죽이고, 타일셋에 맞춘 선은 파생에서 안 걸린다.

### 그런데 새 선을 안 그었다

🔴 **표본이 채택본뿐이다.** 후보 143장은 규약상 안 남긴다(`curated/_manifest.md`).
위 숫자는 사람이 **이미 고른 것**만 모은 것이라, 이걸로 선을 그으면
**합격한 것만 보고 합격선을 정하는 셈**이다. 그리고 실제로 위험하다 —
ΔE 9.2 짜리 타일셋은 **눈으로 보니 멀쩡했다.** 타일셋 경로에 9.0 을 그으면 그 장을 버렸을 것이다.
