# 30_BLOCKS — 프롬프트 부품 (영문)

> 바이블의 한 항목 ↔ 블록 하나. **블록은 바이블을 영어로 옮긴 것이지, 새로 정하는 자리가 아니다.**

> 🔴 **문구를 고치기 전에 [`WRITING.md`](./WRITING.md) 를 본다.**
> *무엇을* 적을지는 바이블이 정하고, ***어떻게* 적을지**는 그 파일이 정한다.
> stage1 앵커 5라운드(20장·125 gen)에서 실측으로 얻은 법칙 10개와 착수 전 체크리스트가 있다.
> 아래 「규칙」이 이 폴더의 형식 규약이라면, 그쪽은 **뜻이 새는 자리**에 대한 것이다.

## 규칙

| | 규칙 | 왜 |
|---|---|---|
| 1 | 모든 블록 헤더에 **어느 바이블 항목에서 왔는가**를 적는다 | 근거 없는 문구가 끼는 것을 막는다. gen1~3이 여기서 샜다 |
| 2 | **한글 주석은 `#` 로만 단다.** `build.py`가 걷어낸다 | 주석이 모델에 넘어가면 지시로 읽힌다 |
| 3 | 도구 파라미터를 여기 쓰지 않는다 | 그건 `40_TOOLS/` 다 |
| 4 | 어휘는 `00_SOURCE/forbidden-vocabulary.md §3` 에서 뽑는다 | |

## 어휘 방침 🔴

**`ruins` · `temple` · `crypt` · `throne` · `void` · `ancient` · `divine` 을 쓰지 않는다.**
전부 소설 0회이고, 넣으면 그 물건이 그려진다.

대신 소설이 실제로 쓰는 것에서 뽑는다 (괄호는 전권 출현 횟수):

```
stone(662)  paper(772)  water(1079)  stairs(199)  wall(242)  house(364)
charcoal(78)  ink(79)  soil(65)  rust(15)  dust(24)  lamp(47)  well(90)
```

> 🔑 **`house`가 `ruins` 자리에 온다.** 소설의 층은 대부분 폐허가 아니다 —
> 8층은 *"집이 많았다. 사람이 많았다"* 이고 `폐허`는 전권 0회다.

## ⚠️ PixelLab 제약 — 블록이 짧아야 한다

PixelLab은 태그 나열형이 아니다. 한 생성의 문구가 길면 **서로 희석되어 아무것도 안 걸린다**
(gen3 실측 지침: 대략 20~35 단어).

그러므로 이 폴더는 **"고를 수 있는 문구 창고"**이고, `50_BUILD/build.py`가 대상마다 필요한 것만 골라 붙인다.
블록을 전부 이어 붙이지 않는다.
